1. EXECUTIVE SUMMARY & CANONICAL PURPOSE
================================================================================
ParishServe is an enterprise-grade ecclesiastical administration and pastoral stewardship
platform engineered specifically for Roman Catholic parishes under the jurisdiction of the
Diocese of San Pablo, Philippines, in strict adherence to the Code of Canon Law
(Codex Iuris Canonici).

The platform digitizes, automates, and connects seven operational pillars:
1. Canonical Sacramental Register Digitization (Canon 535), Pabuklat Requests & Dynamic PDF/QR Certificate Generation.
2. Parish Service Appointments, Mass Intention Scheduling & LitCal Calendar Integration.
3. POS Cashiering, Financial Transactions Ledger, & Particulars Catalog Management.
4. Diocesan Asset Inventory, Reference Catalog, Security Watermarking & Sticker Label Printing (CustodiaIMS).
5. Smart Archive Environmental Telemetry (ESP32 IoT Conservation Monitoring for Vaults & Reliquaries).
6. Daily Catholic Mass Readings & Roman Catholic Lectionary Integration.
7. Multi-Tier Role-Based Access Control (RBAC) Governance & Pastoral Audit Logging.

================================================================================
2. DETAILED USER ROLES & RBAC GOVERNANCE
================================================================================
ParishServe enforces granular Role-Based Access Control across all UI navigation shells,
business logic services, database queries (Row-Level Security / RLS), and API endpoints:

1. Super Administrator ('superadmin' / S)
   - Unrestricted root system authority across all modules, database tables, and settings.
   - User account provisioning, role reassignment, account archiving (`AdminArchivedUsersPage`), and hard account deletion.
   - Global parish branding, certificate templates (`CertificateTemplateManagementPage`), and receipt layout configurations.

2. Administrator ('admin' / A)
   - System administrator managing user governance, asset inventory, smart archive thresholds, and operational diagnostics.
   - Excluded from superadmin-level database override privileges.

3. Parish Priest ('parishpriest' / P)
   - Supreme canonical authority and pastor of St. John Paul II Parish.
   - Full access to all 6 Sacramental Registers (Canon 535), Pabuklat record requests, Tuesday appointment approvals, mass intention approvals, official certificate signatory approvals, marginal notation authorizations, and immutable pastoral audit logs (`pastoral_audit_logs`).

4. Parish Secretary ('secretary' / Sc)
   - Primary operational user for day-to-day parish administration.
   - Manages POS cashiering (`PosCashierPage`), official receipt issuance, particulars catalog management (`ParticularsService`), appointment bookings, sacramental record entry, Pabuklat requests (`PabuklatRequestsModal`, `PabuklatService`), asset label batch printing, and certificate issuance.

5. Records Encoder ('encoder' / E)
   - Data entry specialist focused on field digitization of physical ledger books (Liber Baptismorum, Liber Confirmatorum, etc.), OCR scan verification, and physical asset inventory tagging.

6. Parish Finance Council Auditor ('pfc' / PFC)
   - Financial auditor access for financial receipt reviews, particulars catalog oversight, cashiering reports, remittance exports (`RemittanceReportService`), and diocesan asset valuation.

7. Parishioner / Client ('user' / U)
   - Self-service portal access for parishioners to book parish appointments, request mass intentions, track personal transaction receipts, read daily Catholic mass scriptures, verify official certificate authenticity via QR tokens, and submit Pabuklat requests.

3. EXTERNAL APIS, THIRD-PARTY SERVICES & TECHNICAL STACK
================================================================================
ParishServe integrates a robust suite of cloud services, hardware telemetry APIs, and libraries:

1. Supabase Backend Platform (`supabase_flutter` ^2.17.2)
   - Supabase Auth: Secure user authentication, password reset, and session management.
   - Supabase PostgreSQL Database: Relational database hosting 21 core tables with Row-Level Security (RLS) policies.
   - Supabase Storage Buckets (`certificate-assets`):
     * `issued_pdfs/`: Stores generated official certificate PDF documents.
     * `asset_photos/`: Stores watermarked diocesan property photos.
     * `receipt_logos/`: Stores parish seal and diocesan emblem logos.
   - Supabase Realtime: WebSocket listeners for live in-app notifications (`in_app_notification_service.dart`), smart archive telemetry (`smart_archive_view.dart`), and cashiering updates.
   - Supabase Edge Functions: Deno-based serverless functions (`send-booking-confirmation`).

2. OneSignal Mobile Push Notifications (`onesignal_flutter` ^5.7.0)
   - Delivers real-time push notifications to Android and iOS devices.
   - Synchronizes external user IDs with Supabase Auth UUIDs.
   - Supports role-targeted broadcasts and foreground notification banners.

3. LitCal Liturgical Calendar API (`https://litcal.johnromanodorazio.com/api/dev/calendar/nation/PH`)
   - `LiturgicalCalendarService`: Dynamically queries the LitCal API for Catholic liturgical feast days, liturgical colors, solemnities, and Philippine National Liturgical Calendar events.

4. Roman Catholic Lectionary Daily Mass Readings API
   - `DailyReadingsService` (`DailyReadingModel`): Fetches scripture texts (First Reading, Responsorial Psalm, Second Reading for Sundays/Solemnities, Gospel) with daily liturgical color codes and saint/feast commemorations.

5. Brevo (formerly Sendinblue) Email SMTP API
   - Invoked by Supabase Edge Function `send-booking-confirmation` to send styled HTML email confirmations attached with document submission checklists.

6. ESP32 IoT Micro-Climate Telemetry Protocol
   - Hardware DHT22 sensor telemetry transmitted via HTTP REST / Supabase client from ESP32 microcontrollers into `storage_nodes` and `sensor_telemetry_logs`.

7. PDF Generation & Multi-Format Printing Engine (`pdf` ^3.13.1, `printing` ^5.15.1)
   - Generates vector PDF documents with `pdf_google_fonts` (Arimo, Cousine, Cinzel, EB Garamond, Caveat, Tinos) for TrueType Unicode support of special characters (Ñ, ñ, diacritics) and currency symbols.

8. Public Verification Web Portal & QR Deep-Linking
   - Public verification endpoints:
     * `https://parishserve.web.app/verify?v=<VERIFICATION_TOKEN>` (Certificate verification)
     * `https://parishserve.web.app/verify-receipt?rec=<RECEIPT_NO>` (Receipt transaction verification)

4. CORE OPERATIONAL MODULES & SYSTEM FUNCTIONS
================================================================================

--------------------------------------------------------------------------------
MODULE 1: CANONICAL SACRAMENTAL RECORDS DIGITIZATION, PABUKLAT & CERTIFICATES
--------------------------------------------------------------------------------
Digitizes physical ledger books in full compliance with Canon 535 of the Code of Canon Law:
- Liber Baptismorum (Baptisms)
- Liber Confirmatorum (Confirmations)
- Liber Primae Communionis (First Holy Communions)
- Liber Matrimoniorum (Matrimonies)
- Liber Defunctorum (Deaths & Burials)
- Liber Conversorum (Conversions & Receptions into Full Communion)

Key Features & Business Rules:
1. Physical Coordinates Validation (`SacramentalValidators`):
   - Book Number: Integer 1 - 200
   - Page Number: Integer 1 - 100
   - Line Number: Integer 1 - 10
   - Enforces unique coordinate constraints to prevent duplicate entries.
2. Canon 877 §2 Unwed Paternity Compliance:
   - Safely handles unacknowledged paternity ("Not Indicated" checkbox populates canonical placeholder texts and displays "—" on certificates).
3. Pabuklat Record Search Requests (`PabuklatService`, `PabuklatRequestsModal`):
   - Parishioners submit record search requests for physical ledger inspection ("Pabuklat").
   - Parish secretaries and priests manage, approve, or fulfill Pabuklat requests directly within the registry workflow.
4. Certificate Generation Engine:
   - Supports Simple Mode (structured form flow) and Canva-style Visual Canvas Designer Mode (`CertificateCanvasDesignerPage`) with resizable text, font choices, color pickers, background modes (Full-Page, Border, Plain), and seal/signature placements.
5. Cryptographic QR Verification Tokenization:
   - Generates a non-sequential UUID v4 token (`verification_id`) embedded as a QR code on issued certificates.
   - Public scan resolves recipient name, sacrament type, issue date, canonical book coordinates, and validity status ('Valid' vs 'Revoked').

--------------------------------------------------------------------------------
MODULE 2: PARISH SERVICE APPOINTMENTS & PASTORAL SCHEDULING
--------------------------------------------------------------------------------
Manages bookings for sacraments, pastoral blessings, and mass intentions (`AppointmentService`, `MassIntentionService`).

Service Presets & Durations:
- Nuptial Mass (Wedding): 90 minutes
- Community Baptism: 60 minutes
- Private Baptism: 45 minutes
- Funeral Mass & Blessing: 60 minutes
- Anointing of the Sick & Viaticum: 45 minutes
- House / Business Blessing: 45 minutes
- Thanksgiving Mass Intention: 60 minutes
- Canonical Interview / Pre-Cana: 45 minutes
- Confession & Spiritual Direction: 30 minutes

Canonical Rules & Automated Validation:
1. Monday Prohibition (Clergy Rest Day):
   - Mondays are strictly designated as Canonical Clergy Rest Days and Parish Office closure. Appointments cannot be booked on Mondays.
2. Tuesday Parish Priest Approval Requirement:
   - Tuesday bookings are submitted in 'pending' status and require explicit Parish Priest approval before confirmation.
3. Liturgical Law Blocking (Solemnities & Holy Days):
   - Automatically blocks appointment bookings on Catholic Solemnities, Paschal Triduum, Easter Sunday, Ash Wednesday, All Saints Day (Nov 1), All Souls Day (Nov 2), Christmas Day (Dec 25), Mary Mother of God (Jan 1), Feast of Santo Niño, Immaculate Conception (Dec 8), and Parish Titular Solemnity (St. John Paul II, Oct 22).
4. Operating Window:
   - Service appointments must be scheduled between 06:00 AM and 07:00 PM.
5. Presider & Venue Collision Resolution:
   - Prevents overlapping bookings for the same venue or presider.
6. Automated Email Confirmation:
   - Triggers `send-booking-confirmation` Edge Function to send confirmation emails attached with service document checklists.

--------------------------------------------------------------------------------
MODULE 3: POS CASHIERING, RECEIPTS & FINANCIAL MANAGEMENT
--------------------------------------------------------------------------------
Handles parish cashiering, mass intention offerings, and official receipt management:
- Particulars Catalog (`ParticularsService`): Service items and stipend amounts across Sacraments, Mass Intentions, Certificates, Devotionals, and Others.
- POS Cashiering Interface (`PosCashierPage`): Shopping cart UI supporting Cash (with tendered & change calculation), GCash/E-Wallet (with reference validation), and Gratis (canonically exempt).
- Sequential Receipt Numbering: Format `REC-YYYY-XXXXX`.
- Canvas Receipt Template Designer (`ReceiptCanvasDesignerPage`): Design support for Ecclesiastical Voucher Slips (8.5 x 4.125 in), A4, Letter, Legal (8.5 x 13 in), and 80mm Thermal Receipt Rolls.
- Multi-Format Printing & Financial Reports: PDF issuance with amount-in-words conversion, itemized lines, QR tokens, and remittance export reports (`RemittanceReportService`).

--------------------------------------------------------------------------------
MODULE 4: DIOCESAN ASSET INVENTORY (CustodiaIMS)
--------------------------------------------------------------------------------
Provides diocesan property tracking, reference catalog management, security watermarking, sticker label printing, and mobile field auditing:
- Diocesan Control Number System: Continuous control format `Location-Classification Year-Sequence` (e.g. `C-SI-2026-001`).
- Book of Inventory Section Classification:
  * Section 1: Acquisition price per unit ≥ ₱10,000.00
  * Section 2: Acquisition price per unit < ₱10,000.00
- Reference Management (`AssetReferenceService`): Dynamic locations (Church, Sacristy, Office, Pastoral Office, PEAC, Multi-Purpose Hall, Others) and classifications (Sacred Image, Sacred Vessel, Musical Instrument, Liturgical Book, Furniture, Office Equipment, Electrical, Hand Tools, Others).
- Automated Security Watermarking (`AssetImageWatermarkUtil`): Embeds native canvas security watermark onto uploaded asset photos containing parish name, timestamp, and Diocesan Control #.
- Asset Label PDF Generation (`AssetLabelPdfService`): Generates 70mm x 38mm sticker labels and batch A4 sheets (3x8 grid = 24 labels/page) with QR code tokens.
- RFID / NFC Tag Integration: Native 13.56 MHz RFID/NFC UID reading for sacred metal vessels and high-value furnishings.
- Mobile Field Audit Scanner (`_AuditScanDialog`): Continuous field audit workflow using live camera scanner, NFC reader, or manual barcode lookup.

--------------------------------------------------------------------------------
MODULE 5: SMART ARCHIVE ENVIRONMENTAL TELEMETRY (ESP32 IoT)
--------------------------------------------------------------------------------
Real-time micro-climate monitoring for sacramental record vaults and sacred artifact conservation:
- Conservation Standards:
  * Temperature Range: Ideal 18.0 °C – 24.0 °C (Warning > 26.0 °C)
  * Relative Humidity (RH) Range: Ideal 45% – 55% RH (Warning > 60% RH to prevent mold growth and paper degradation)
- Node Telemetry Ingestion: ESP32 DHT22 sensors transmit readings into `storage_nodes` and `sensor_telemetry_logs` with real-time warning indicators.

--------------------------------------------------------------------------------
MODULE 6: DAILY CATHOLIC MASS READINGS & LECTIONARY
--------------------------------------------------------------------------------
Integrates Roman Catholic Lectionary scripture texts (`DailyReadingsService` / `DailyReadingsCard`):
- Displays daily First Reading, Responsorial Psalm, Second Reading (Sundays/Solemnities), and Gospel text.
- Indicates daily liturgical color (White, Gold, Red, Green, Violet, Rose) and Saint/Feast commemorations.

--------------------------------------------------------------------------------
MODULE 7: DASHBOARDS, USER GOVERNANCE & AUDIT LOGGING
--------------------------------------------------------------------------------
Specialized navigation shells (`AdminNavigationShell`, `MainNavigationShell`, `ParishionerNavigationShell`) and dashboards:
- Admin & Staff Dashboard: High-level overview of appointments, revenue, asset counts, archive alerts, and pending approvals.
- Parishioner Dashboard: Personal appointment status, mass intention history, receipt ledger, and daily readings.
- Immutable Audit Logs: `pastoral_audit_logs` for canonical priest overrides and `asset_audit_logs` for physical property inspections.
